The E-Commerce Sales Analytics Dashboard is a data analysis project that explores an e-commerce sales dataset and presents its findings through a website. The project uses Python in a Jupyter Notebook to load, prepare, analyze, and model the data. The results and selected visualizations are then presented in a standalone HTML dashboard. The main purpose is to understand sales performance, identify patterns in customer purchases, examine delivery and customer satisfaction, and explore whether order revenue can be estimated using machine-learning models.
What the Dataset Is About
The dataset used in this project is named E-Commerce Sales Analytics and contains 5,000 order transactions with 12 columns. Each row represents an order transaction. It covers orders dated from January 1, 2022, to May 9, 2025. The dataset includes transaction identifiers such as order_id and customer_id, as well as the date each order was placed through order_date. It also records the product category, sales region, and payment method used for each transaction.

The dataset contains numerical information that helps describe each purchase and its fulfillment. The quantity column records the number of items purchased, while unit_price records the price per item and discount records the discount applied. The delivery_days column shows how long the order took to be delivered, and customer_rating records the customer's rating of the order. The revenue column represents the transaction revenue and is the target variable used by the notebook's revenue-prediction models. The product categories in the notebook are Beauty, Clothing, Electronics, and Home; the regions are North, South, East, and West; and the payment methods are Card, Wallet, and Cash on Delivery (COD). The values are expressed in the dataset's stated units, with prices and revenue shown in dollars.
Project Process
The process begins by loading the CSV file, E-Commerce Sales Analytics.csv, into Python using pandas. The notebook includes path-detection code to help locate the dataset in supported environments, including a local project folder. After loading the file, the notebook displays sample records, column information, descriptive statistics, and missing-value counts so the data can be inspected before analysis. The order_date field is converted into a date format, extra spaces are removed from text fields, duplicate rows are checked and removed if present, and the records are arranged chronologically.

After the data is prepared, exploratory data analysis is performed to understand the information in the dataset. Histograms are used to examine the distributions of revenue, unit price, discount, quantity, customer ratings, and delivery duration. Line graphs show monthly changes in total revenue, average revenue per order, order volume, average customer rating, average unit price, and average delivery time. Bar charts and count plots compare order counts and revenue across product categories, regions, and payment methods. Pie charts show the share of revenue or orders across categories, regions, payment methods, rating groups, delivery-speed groups, and order quantities.

The notebook also includes predictive and advanced analysis. Time-series methods are used to examine historical revenue patterns and produce a forecast. Several regression models are trained to estimate order revenue using information such as product category, region, payment method, quantity, unit price, discount, delivery duration, and customer rating. The notebook compares model performance using evaluation measures such as R-squared, root mean squared error, and mean absolute error. It also includes feature-importance explanations using methods such as SHAP and LIME, anomaly-detection methods to identify unusual transactions, and clustering techniques to explore groups of similar orders. These methods are analytical tools; their results should be interpreted in the context of the dataset and do not automatically prove why a particular customer or transaction behaved in a certain way.

When the analysis is complete, selected charts and findings are presented in Index.html. The HTML file is the presentation layer of the project: it displays the dashboard title, KPI summary cards, charts, forecasting and model-evaluation visuals, and dataset information. Python performs the calculations and creates the analysis; the HTML page displays selected results in a browser.
Website and Project Files
The Jupyter Notebook, named e-commerce-analytics-eda-ml-forecast-fixed-v2.ipynb, contains the Python code for data loading, cleaning, exploration, visualization, forecasting, and machine-learning analysis. The Data folder contains the original CSV dataset. The Index.html file contains the website dashboard, while the README.md file explains the project. The .gitignore file tells Git to leave out local or temporary files such as the Python virtual environment, Python cache files, and Jupyter checkpoint folders. Other folders, such as dashboard_data, Image, and images, may be used for exported results or image assets as the project develops.
How to Run the Project
To run the analysis, open the project folder in Visual Studio Code and open the Jupyter Notebook. Make sure the required Python libraries are installed and select the correct Python environment or notebook kernel. Confirm that E-Commerce Sales Analytics.csv is available in the expected Data folder, then run the notebook cells in order. If the notebook reports that the dataset cannot be found, check the filename and folder location and make sure the path-detection code can locate it. The CSV-loading statement should use the variable dataset_path, as in pd.read_csv(dataset_path), without quotation marks around the variable name.

To view the website locally, open Index.html in a web browser. You can double-click the file from your computer, or use the Live Server extension in Visual Studio Code if it is installed. The website is a static HTML page and does not run Python code in the browser. The charts currently embedded in the page are image snapshots taken from the notebook's outputs. They will not update automatically when the dataset or notebook changes. To refresh the displayed charts, rerun the relevant notebook cells, save the updated chart images, and replace the existing chart images in the HTML page.
GitHub and Publishing
The project can be stored in a GitHub repository so its source files and documentation can be shared. The .gitignore file should exclude local environment and temporary files, especially .venv, __pycache__, and .ipynb_checkpoints. Keep the HTML page and any image or exported data files that the website needs. Before uploading the original CSV, check that its license and usage conditions allow redistribution. To publish the static website, upload the required website files to GitHub, open the repository's Settings, go to Pages, choose deployment from a branch, and select the branch and folder containing the homepage. GitHub Pages uses index.html as the conventional default homepage filename, so rename Index.html to index.html if needed.
Project Goal
This project demonstrates how an e-commerce dataset can be processed and analyzed to understand revenue, purchasing patterns, product categories, regional performance, payment preferences, delivery operations, and customer ratings. It also demonstrates how forecasting, regression, explainable machine learning, anomaly detection, and clustering can be used to explore the data further. The final HTML dashboard provides a clear visual summary of selected results so that readers can understand the analysis without needing to inspect every cell in the Python notebook.
